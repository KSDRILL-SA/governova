PART 1 / RULES 1–10 Architecture 7 Critical · 3 High · Applies to Next.js + Angular
RULE 1One Adaptive System Per Platform — Never Two Separate BuildsCritical
BOTH STACKS

Each platform has ONE codebase that adapts to all screen sizes. Never build a separate mobile site, separate app, or separate URL structure. One repo, one deployment, all devices.

Next.js
Next.js App Router with responsive components. Same app/ directory serves all devices via CSS responsive design.
Angular
Single Angular SPA with responsive components. Same Angular routes serve all devices — no mobile subdomain, no separate Angular app.
RULE 2Mobile-First — 320px BaselineCritical
BOTH STACKS

All CSS starts at 320px and scales up. No component is designed desktop-first. Tailwind utilities use mobile-first breakpoints: sm: md: lg: — never start with desktop layout and override down.

!
Violation: Writing hidden md:block on primary content (hiding from mobile is not mobile-first — restructure the component instead).
RULE 3Brand Always Visible — Minimum 20px LogoCritical
BOTH STACKS

Platform logo or brand name must be visible on every page at all screen sizes. Minimum rendered height 20px. Never collapse brand on mobile. Never hide behind a hamburger menu.

RULE 4Hero Sections Use min-height — Never Fixed HeightHigh
BOTH STACKS

Hero sections must use min-h-screen or min-height: 100dvh. Never use height: 100vh (breaks on mobile browser chrome) or fixed pixel heights.

RULE 5Visual Regression Tests at 320 / 375 / 390px — MandatoryCritical
BOTH STACKS

CI must run visual regression tests at exactly 320px, 375px, and 390px viewport widths on every PR. Any layout breakage at these widths is a build failure. Tests live in tests/visual/.

Next.js
Playwright visual tests + lighthouserc.js
Angular
Playwright visual tests in e2e/visual/
RULE 6Navigation — Horizontal at Desktop, Structured at MobileCritical
BOTH STACKS

Desktop navigation is horizontal with dropdowns. Mobile navigation is a bottom sheet or horizontal scroll — NEVER an accordion or full-page overlay.

RULE 7Hamburger Opens Horizontal Dropdown — Never AccordionCritical
BOTH STACKS

If a hamburger menu is used, it must open a horizontal dropdown panel. Accordion-style expanding menus that push page content down are forbidden on all screen sizes.

RULE 8Sticky Headers — Shrink on Scroll, Never Obscure ContentHigh
BOTH STACKS

Sticky headers must shrink on scroll (reduced padding/height). Add scroll-padding-top equal to header height so anchor links land correctly. Header must never obscure critical content.

RULE 9Mobile Bottom Sheet or Horizontal Scroll for Secondary NavigationCritical
BOTH STACKS

Secondary navigation on mobile (tabs, categories, filters) uses either a bottom sheet drawer or a horizontally scrollable row. Never stack vertically or use an accordion.

RULE 10No Horizontal Scroll on Page — Only Inside Explicit ContainersHigh
BOTH STACKS

The page body must never horizontally scroll at any screen width. Horizontal scroll is only permitted inside explicitly bounded containers (e.g., overflow-x: auto on a table wrapper). Add overflow-x: hidden to body.

PART 2 / RULES 11–20 Interaction & Accessibility 3 Critical · 7 High · Both Stacks
RULE 11Touch Targets — 44×44px Mobile, 32×32px DesktopCritical
BOTH STACKS

Every interactive element (button, link, icon button) must be at minimum 44×44px on mobile and 32×32px on desktop. Use padding, not width/height, to meet this requirement without breaking layout.

RULE 12Body Text Minimum 16px — No Smaller in Running TextHigh
BOTH STACKS

All paragraph text, form labels, input values, and descriptions must be minimum 16px (1rem). Captions and metadata may go to 12px but never in running text. Never use text-xs on body copy.

RULE 13Respect prefers-reduced-motion — All Animations ConditionalHigh
BOTH STACKS

All animations and transitions must be wrapped in a @media (prefers-reduced-motion: no-preference) check. Disable or minimise motion when prefers-reduced-motion: reduce is set.

RULE 14Full Keyboard Accessibility — Tab, Enter, Escape, Arrow KeysCritical
BOTH STACKS

Every interactive element must be reachable and operable by keyboard alone. Tab navigates focus, Enter activates, Escape closes dialogs/drawers. Custom components (dropdowns, modals) must implement full ARIA keyboard patterns.

Next.js
shadcn/ui components include keyboard patterns by default. Custom components use useKeyboardNavigation hook.
Angular
Angular CDK A11yModule and FocusTrap for dialogs. Use Angular CDK ListKeyManager for list navigation.
RULE 15WCAG 2.1 AA Colour Contrast — 4.5:1 for Normal TextCritical
BOTH STACKS

All text must meet WCAG 2.1 AA minimum contrast ratios: 4.5:1 for text below 18px, 3:1 for text 18px or larger. Run automated contrast checks in CI using axe-core. No exceptions for brand colours.

RULE 16No Emojis in UI Code — Icons OnlyHigh
BOTH STACKS

Emojis are forbidden in UI component code (JSX, Angular templates, CSS content). Use Lucide icons → Heroicons → custom SVG instead. Emojis are permitted only in user-generated content display.

Enforcement
ESLint rule: no-emoji-in-ui in both repos
RULE 17Icon Priority Chain — Lucide → Heroicons → Custom SVGHigh
BOTH STACKS

Always check Lucide first. If the icon doesn't exist, check Heroicons. If still absent, create an inline SVG. Never use <img> for icons. Never use Font Awesome or other icon fonts.

RULE 18Focus Rings — Visible and Never RemovedHigh
BOTH STACKS

Focus rings must be visible on all interactive elements. Never apply outline: none or outline: 0 without an equivalent visible focus indicator. Use :focus-visible to show rings only on keyboard navigation.

RULE 19All Images Have Alt Text — Decorative Images Use alt=""High
BOTH STACKS

All <img> elements must have an alt attribute. Meaningful images need descriptive alt text. Decorative images use alt="" (empty string, not absent). CI fails if any image is missing alt.

RULE 20Semantic HTML — Headings in Order, Landmark Roles PresentHigh
BOTH STACKS

Use semantic HTML elements: <nav>, <main>, <header>, <footer>, <section>. Heading levels (h1–h6) must be in logical order — never skip from h1 to h3. One h1 per page only.

PART 3 / RULES 21–38 State & Data 7 Critical · 5 High · Stack-differentiated
RULE 21Tailwind for Layout — Custom CSS for Visual ComplexityHigh
BOTH STACKS

Tailwind handles layout, spacing, and typography. Custom CSS handles animations, gradients, glassmorphism, and complex visual effects. Never use Tailwind @apply to replicate custom animation patterns.

RULE 22Custom CSS Files — Max 100 Lines Each, Named by PurposeHigh
BOTH STACKS

Custom CSS files are split by concern and capped at 100 lines each: animations.css, components.css, glassmorphism.css. The exception is print.css (exempt from line limit).

RULE 23Use theme() — Never Hardcode Colour Values in CSSMedium
BOTH STACKS

In custom CSS files, always reference colours via theme('colors.primary.500') or CSS custom properties. Never write hex or rgb values directly in custom CSS. All colour tokens live in the Tailwind config.

RULE 24No Inline Styles — Configuration Files and CSS Classes OnlyMedium
BOTH STACKS

Inline style attributes are forbidden except for dynamic values that cannot be expressed via class (e.g., CSS custom property overrides from JavaScript/TypeScript). All static styles use Tailwind classes or CSS files.

RULE 28Every Async Operation: Skeleton + Error + Success StatesCritical
BOTH STACKS

No async operation (data fetch, form submit, file upload) can show a blank screen. Every async op must implement three states: (1) skeleton/loading placeholder, (2) error state with message, (3) success state with data.

Next.js
TanStack Query: isLoading → skeleton, isError → error component, data → render. Use loading.tsx for route-level skeletons.
Angular
RxJS: Use AsyncPipe with *ngIf or Angular Signals. Implement three template blocks: @if (loading), @else if (error), @else.
RULE 29Inline Form Validation — Error Under Every FieldCritical
BOTH STACKS

Form validation errors appear inline, immediately below the field they apply to. Never use a toast or page-level banner for field validation. Error text must be minimum 12px, coloured red, with an associated aria-describedby.

Next.js
React Hook Form formState.errors rendered below each <Input>. Zod schema errors surface via zodResolver.
Angular
Angular Reactive Forms: formControl.errors checked on touched && dirty. Error messages defined in validator, shown via *ngIf or @if.
RULE 30Validate Every API Request AND Response — From OpenAPI ContractCritical
BOTH STACKS

Every API request body must be validated before sending. Every API response must be validated on receipt. Never manually write frontend validation schemas — generate them from the OpenAPI contract.

Next.js
Zod schemas generated via openapi-zod-client. Validate with schema.parse(response). Pre-commit hook enforces no manual schemas.
Angular
TypeScript client generated via openapi-typescript or Angular OpenAPI generator. Types enforce contract — Pydantic shapes must match Angular validator shapes.
RULE 31No Business Logic in UI ComponentsCritical
BOTH STACKS

UI components render and handle interaction only. Business logic lives in service layers, hooks, or utilities — never in component files.

Next.js
Custom hooks (useXxx) contain logic. Components call hooks and render results. No fetch() directly inside JSX.
Angular
Angular Services (@Injectable) contain all business logic. Components call service methods. No HTTP calls from component class directly.
RULE 32No Hardcoded Values — Configuration Files OnlyCritical
BOTH STACKS

Navigation items, theme tokens, API URLs, feature flag keys, and role constants must live in configuration files — never hardcoded in components. All config files are in lib/config/ (Next.js) or src/environments/ (Angular).

RULE 33Server State vs Client State — Never Mix ConcernsCritical
BOTH STACKS

Server/remote data lives in dedicated async state management. Local UI state (open/closed toggles, form draft, scroll position) lives separately. Never put server data into local state management and vice versa.

Next.js
TanStack Query for server state. Zustand slices for client-only state. URL (searchParams) for shareable/refreshable state.
Angular
RxJS + Angular Services for server state. Angular Signals for local component state. Angular Router for URL state.

PART 4 / RULES 67–72 Angular Framework Rules FundsLink Academy · Reserve Bank only
!
Angular-Only Section: Rules 67–72 are additive to Rules 1–66. Angular systems must comply with ALL rules in Parts 1–3 and 5–6, PLUS these Angular-specific rules. Next.js systems do not implement Rules 67–72.
RULE 67Reactive Forms Only — Never Template-Driven FormsCritical
ANGULAR ONLY

All Angular forms use Reactive Forms (FormGroup, FormControl, FormArray). Template-driven forms (ngModel, [(ngModel)]) are forbidden in production code. Reactive Forms give compile-time safety, explicit validation, and easier testing.

❌ Template-Driven — Forbidden
<input [(ngModel)]="email"
  name="email">
✅ Reactive Forms — Required
this.form = this.fb.group({
  email: ['', [Validators.required,
          Validators.email]]
});
RULE 68HTTP Interceptor — JWT + X-Request-ID on Every RequestCritical
ANGULAR ONLY

All HTTP requests must pass through a single Angular HTTP Interceptor that: (1) attaches the Authorization: Bearer <token> header, (2) generates and attaches X-Request-ID: crypto.randomUUID(), (3) handles 401 responses to trigger token refresh or redirect to login.

auth.interceptor.ts
export const authInterceptor: HttpInterceptorFn = (req, next) => {
  const token = inject(AuthService).getToken();
  const requestId = crypto.randomUUID();
  const authReq = req.clone({
    setHeaders: {
      'Authorization': `Bearer ${token}`,
      'X-Request-ID': requestId      // Rule 61 compliance
    }
  });
  return next(authReq).pipe(
    catchError(err => {
      if (err.status === 401) inject(AuthService).logout();
      return throwError(() => err);
    })
  );
};
RULE 69Angular Route Guards — All Protected Routes Use AuthGuardCritical
ANGULAR ONLY

Every authenticated route must use an Angular Route Guard (canActivate) to verify token validity before activating. Guards redirect unauthenticated users to /login. Role-based route access uses a separate RoleGuard.

AuthGuard checks
Token present + not expired
RoleGuard checks
Token role matches route role (STUDENT, FUNDER, ADMIN)
On failure
Redirect to /login with returnUrl queryParam
RULE 70Standalone Components — No NgModules in New CodeHigh
ANGULAR ONLY

All new Angular components use standalone: true with direct imports. NgModules are not created for new features. Existing NgModules may remain but must not be extended with new components — migrate components to standalone instead.

❌ NgModule Pattern — No New Code
@NgModule({
  declarations: [DashboardComponent],
  imports: [CommonModule]
})
✅ Standalone Component
@Component({
  standalone: true,
  imports: [CommonModule, RouterModule],
  template: `...`
})
RULE 71OnPush Change Detection — Required on All ComponentsHigh
ANGULAR ONLY

All Angular components must use changeDetection: ChangeDetectionStrategy.OnPush. Default change detection is forbidden on production components. Use Angular Signals or Observable + AsyncPipe to trigger updates within OnPush components.

i
Why: OnPush prevents unnecessary re-renders on large dashboards (FundsLink multi-role, Reserve Bank live balance). Financial data at scale demands OnPush — default strategy will cause performance failures under real load.
RULE 72Angular Testing — Vitest for Unit, Playwright for E2EHigh
ANGULAR ONLY

Angular unit and component tests use Vitest with Angular Testing Utilities (not Karma/Jasmine — those are legacy). End-to-end tests use Playwright. Visual regression tests run Playwright at 320/375/390px. CI must run all three test layers on every PR.

Unit Tests
Vitest + TestBed · Services, Guards, Interceptors
Component Tests
Vitest + ComponentFixture · Rendered output, form validation
E2E Tests
Playwright · Critical auth + feature paths
Visual Regression
Playwright at 320/375/390px — Rule 5 compliance

PART 6 / RULES 61–66 Observability 4 Critical · 2 High · Both Stacks
RULE 61X-Request-ID — Generate UUID, Forward on Every API CallCritical
BOTH STACKS

Every API call must include a X-Request-ID: crypto.randomUUID() header. When an error is shown to the user, display the request ID so support can trace the exact request. The ID must be forwarded to FastAPI and logged at every layer.

Next.js
Centralised in lib/api/client.ts fetch wrapper. Appended to every outgoing fetch call automatically.
Angular
Implemented in the HTTP Interceptor (Rule 68). X-Request-ID is set per-request in the interceptor — not per service.
RULE 62Centralized Error Handler — Map Every Code to a User MessageCritical
BOTH STACKS

A single error handler maps all backend error codes to user-facing messages. Never display raw error codes, stack traces, or internal messages to the user. The handler lives in one file and all API calls funnel through it.

Next.js
lib/api/error-handler.ts — switch on error.code, return user string. Used by fetch wrapper and TanStack Query onError.
Angular
error-handler.service.ts — @Injectable service. HTTP Interceptor pipes errors through it. Exposed as Observable<string> for templates.
RULE 63429 Rate Limit UX — Disable Button, Show Countdown, BackoffCritical
BOTH STACKS

When a 429 response is received: (1) disable the submit button, (2) display a countdown timer using the Retry-After header value, (3) re-enable automatically when the countdown reaches zero. Exponential backoff applies to automatic retries — never retry immediately after a 429.

RULE 64WebSocket — Reconnection Logic + Offline QueueHigh
NEXT.JS ONLY (SyncUp)

WebSocket connections (/ws/chat — SyncUp only) must implement: (1) automatic reconnection with exponential backoff, (2) an offline message queue that drains on reconnect, (3) a visible connection status indicator. Only one WebSocket endpoint is permitted in v1.

RULE 65Feature Flags — Consume from Backend, Cache 5 MinutesHigh
BOTH STACKS

Feature flags are fetched from the backend at startup and cached for 5 minutes. Never hardcode feature flag values in the frontend. New features ship behind a flag by default — enable via backend, not a frontend deploy.

Next.js
useFeatureFlag(key) hook fetches from /api/v1/features via TanStack Query with 5min staleTime.
Angular
FeatureFlagService fetches flags on app init. Returns Signal<boolean> per flag key. Angular Route Guards check flags for feature routes.
RULE 66Cross-Constitution Governance — Frontend Review Required on API ChangesCritical
BOTH STACKS

Any pull request that changes the OpenAPI contract, ApiResponse shape, error codes, or rate limit tiers must include a Frontend-Review-Required: Yes label. CI fails without this label on cross-constitution changes. This applies across all 10 constitutions — not just FE and BE.
