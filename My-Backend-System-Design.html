§ Part 1 — Architecture & Boundaries (B1–B6)

Define who does what. No confusion. No overlap. The service boundary is the backbone of the entire system.

Service Ownership
  • Next.js Auth, CRUD, Payments
  • Next.js Orchestration, Proxy
  • FastAPI AI, RAG, Predictions

FastAPI

PART 1 / B1–B6 Architecture & Boundaries 5 Critical · 1 High
B1Service Responsibility BoundaryCritical

Next.js API Routes = auth, CRUD, payments, orchestration. FastAPI = AI, predictions, RAG, agents. NEVER cross responsibilities.

❌ Violation
// OpenAI call in Next.js API route
const result = await openai.chat.completions.create({...});
✅ Correct
// Next.js proxies to FastAPI
const result = await fetch('/ai/predict', { ... });
B2Single Gateway PrincipleCritical

Frontend NEVER calls FastAPI directly (except WebSocket /ws/chat). All requests proxy through Next.js API Routes.

Enforcement
CORS config + network policy
Exception
WebSocket /ws/chat only — if chat is v1 core
B3FastAPI Internal-OnlyCritical

FastAPI endpoints are internal-only. Require X-Internal-API-Key header from Next.js. Never exposed to public internet.

B4FastAPI — No PostgreSQL WritesCritical

FastAPI has NO database writes to PostgreSQL. Reads ChromaDB only. State changes call Next.js webhook instead.

Violation
FastAPI does INSERT INTO users
Compliance
POST /api/internal/webhook/user-update
B5FastAPI Endpoint Proxy RequirementHigh

Every FastAPI endpoint has a corresponding Next.js API route that proxies it. Both documented in OpenAPI contract.

B6One-Way Communication OnlyCritical

Next.js → FastAPI communication is ONE-WAY only. Never circular. FastAPI may call Next.js webhook (one-way, no response expected) — never the reverse loop.

PART 2 / B7–B12 API Contract 5 Critical · 1 High
B7OpenAPI First PrincipleCritical

OpenAPI 3.0 contract MUST exist before ANY endpoint code. PR shows OpenAPI changes BEFORE code changes. CI fails if contract is missing or incomplete.

B8Standard Response Format — ApiResponse<T>Critical

ALL responses follow ApiResponse<T> format across both services. No exceptions.

types/api.ts
type ApiResponse<T> = {
  success: boolean;
  data: T | null;
  error: {
    code: string;
    message: string;
    field?: string;  // validation errors only
  } | null;
  meta?: {
    pagination?: {
      page: number; limit: number;
      total: number; pages: number;
    };
  };
}

B10Frontend Zod Generation from OpenAPICritical

Frontend generates Zod schemas from OpenAPI via openapi-zod-client. NEVER manually write frontend validation schemas. Pre-commit hook enforces this.

B11Validation ParityCritical

Next.js validates with Zod, FastAPI with Pydantic. Both must match OpenAPI exactly. If Next.js requires email, FastAPI must too.

B12Error Transformation — FastAPI → ApiResponseCritical

FastAPI errors are transformed by Next.js API Routes to match ApiResponse<T> before reaching the frontend. Raw FastAPI errors must never reach the client.

❌ Raw FastAPI error exposed
{ "detail": "Pydantic error..." }
✅ Transformed in Next.js
catch (err) { return formatApiError(err) }

PART 3 / B13–B18 Database 4 Critical · 2 High
B13Prisma as Source of TruthCritical

Prisma schema is the source of truth. All migrations through Prisma. Raw SQL is allowed ONLY for complex aggregates/recursive CTEs — and must include a comment explaining why.

B14Required Table FieldsHigh

Every table must have: id (UUID/cuid), created_at (@default(now())), updated_at (@updatedAt). Enforced by Prisma schema lint in CI.

B15FastAPI — No Database AccessCritical

FastAPI never touches PostgreSQL. All DB access through Next.js API Routes. Network policy blocks direct PostgreSQL connection from FastAPI container.

B16Database Separation — Postgres vs ChromaDBCritical

Separate data by purpose: PostgreSQL stores relational data (users, profiles, applications). ChromaDB stores vector embeddings (documents, RAG context). Never mix the two.

!
Violation: Storing embeddings in PostgreSQL (even with pgvector extension) creates a single point of failure and makes both systems harder to scale and maintain independently.
B17Cross-Database Sync PatternHigh

When PostgreSQL changes affect ChromaDB (e.g., user profile update): Next.js API → FastAPI webhook → ChromaDB update. Integration test must verify sync.

B18Selective Field Selection — No SELECT *Critical

All Prisma queries use select to return only needed fields. Never expose password_hash, reset_token, refresh_token, etc.

❌ Exposes sensitive fields
prisma.user.findMany() // no select
✅ Explicit safe fields
prisma.user.findMany({
  select: { id: true, email: true }
})

B205 Gate Questions — Every v1 EndpointCritical

5 gate questions for EVERY v1 endpoint in both backends. One "no" = defer to v2. PR template requires completed checklist before merge.

G1Does this endpoint serve a v1 core feature (from Frontend Group 2)?NO → v2

B21No Background Jobs in v1High

No BullMQ/Redis background jobs in v1. Use sync or sequential. Add queues in v2 if needed. If an operation takes <3s, do it synchronously within the request.

B22WebSocket RestrictionHigh

No WebSocket in v1 except /ws/chat — ONLY if chat is a core MVP feature. Otherwise, HTTP polling every 5 seconds for real-time-like features.

B23Model Startup LoadingCritical

FastAPI models load at startup via lifespan and cache in app.state.models. Never load models during request handling. One cold start vs. every request slow is the difference between usable and unusable.

❌ Loads on every request
async def predict(input):
  model = load_model()  # FORBIDDEN
✅ Loaded once at startup
@asynccontextmanager
async def lifespan(app):
  app.state.model = load_model()

B25OpenAI Call ResilienceCritical

FastAPI calls to OpenAI: 30s timeout + 3 retries (exponential backoff: 1s/2s/4s) + fallback to cached response or graceful error.

services/openai_client.py
async with asyncio.timeout(30):
  for attempt in [1, 2, 4]:  # backoff seconds
    try:
      result = await openai_call()
      return result
    except RateLimitError:
      await asyncio.sleep(attempt)
# fallback to cache or graceful error
return cached_response or graceful_error()

B43Cross-Service ConsistencyCritical

Cross-service operations (Next.js → FastAPI → DB) must be: idempotent (retryable) OR have a compensating action (rollback). Never leave the system in an inconsistent state.

!

B45Security BaselineCritical

PART 9 / F1–F15 FastAPI-Specific Rules 7 Critical · 8 High
F1Model Startup Loading — lifespanCritical

Models load ONCE at startup, stored in app.state.models. Never reload per request. Use lifespan context manager.

main.py
@asynccontextmanager
async def lifespan(app: FastAPI):
    # Startup — load all models once
    app.state.models = {
        "sentiment": load_model("sentiment-v1"),
        "embedding": load_model("embedding-v2"),
    }
    yield
    # Shutdown — cleanup
    for model in app.state.models.values():
        model.cleanup()
F2Idle Model Unloading — 30minHigh

Unload unused models after 30 minutes idle. Warm-up allowed on next request. GPU memory is expensive — keeping 5 models loaded for 1 user is wasteful.

F3Concurrency LimitingCritical

Set max_concurrent_requests = os.cpu_count() * 2. Never unlimited. Python GIL limits concurrency — use asyncio.Semaphore.

middleware/concurrency.py
max_concurrent = os.cpu_count() * 2
semaphore = asyncio.Semaphore(max_concurrent)

async def predict(request):
  async with semaphore:
    # safe — bounded concurrency
    return await run_inference(request)
F4 + F5Batch Predictions · Model VersioningHigh

F4: Batch predictions when possible — one request with 10 items vs. 10 requests. GPU calls have overhead; batching = 10× throughput. F5: Model versioning via /v1/predict, /v2/predict with deprecation headers for canary rollouts.

F6 + F7async def / def Correctness + Thread PoolCritical

F6: Use async def for I/O (HTTP calls, ChromaDB). Use def for CPU-bound (model inference). Wrong choice blocks the event loop. F7: Run CPU-bound inference in asyncio.to_thread() or a separate process pool.

❌ Blocks event loop
async def predict(data):
  result = model.infer(data) # CPU blocks!
  return result
✅ Non-blocking
async def predict(data):
  result = await asyncio.to_thread(
    model.infer, data
  )
  return result
F8External Call Timeouts — 30sCritical

Set 30s timeout for ALL external calls (OpenAI, ChromaDB, etc.) via asyncio.timeout(). No call hangs indefinitely.

❌ Can hang forever
result = await openai.ChatCompletion.create(...)
✅ Bounded by 30s
async with asyncio.timeout(30):
  result = await openai_call()
F11Token Counting + Budget GuardCritical

Implement token counting + budget guard: reject requests exceeding max_tokens × 1.5. One rogue request can cost $10. This rule pays for itself on day one.

F12 + F13OpenAI Response Caching · ChromaDB Separate ContainerHigh

F12: Cache identical OpenAI responses for 1 hour (key = prompt_hash + temperature). Reduces cost 50–80% for repeated queries. F13: ChromaDB runs in a separate container — not in-memory in FastAPI. Ensures persistence across restarts.

F14Similarity Score Threshold — 0.7 MinimumHigh

Similarity search with min_score = 0.7 threshold. Reject low-confidence results. Below 0.7 returns "No relevant results found" rather than wrong answer with false confidence.

F15Detailed Health Check ResponseHigh

Health check must tell Next.js WHY it's unhealthy — not just that it is.

{ "status": "healthy", "models_loaded": ["sentiment-v1", "embedding-v2"], "chromadb_connected": true, "chromadb_collections": 3, "openai_available": true, "openai_latency_ms": 120, "queue_depth": 0, "concurrent_requests": 2, "max_concurrent": 10, "uptime_seconds": 86400 }
