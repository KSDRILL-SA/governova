§ 02

The Golden Rule

Immutable
Build constitutions in the order your system would fail without them.

Every constitution in this order exists because the system would break — architecturally, securely, or operationally — if that constitution's rules were absent. Phase 0 constitutions are first because without team process and code quality, nothing else holds. Phase 1 constitutions are next because without a working architecture, auth, frontend, and database, there is nothing to test or deploy. Phase 2 adds reliability. Phase 3 adds product intelligence.

Violating this order — building features before establishing the architecture, or deploying before establishing incident response — is the root cause of every "we have to rewrite this" situation in software.
v3.0 Dual-Stack Note: The constitutional order applies identically to both stacks. Whether building FundsLink (Angular + FastAPI) or Maphophe (Next.js), the same 10 constitutions govern in the same order. The difference is which stack-specific rules within each constitution apply — identified throughout the v3.0 documents by scope badges.
§ 03

Amendment Protocol — How Rules Change

Governance
Step 1 — Propose
Document the Gap
Open a GitHub Issue in system-design-template tagged constitutional-amendment. Describe: (1) which constitution, (2) which rule, (3) why the current rule is insufficient or incorrect, (4) the proposed new rule text. Evidence required — not just preference. Incidents, post-mortems, and build learnings are the strongest evidence.
Step 2 — Review
48-Hour Open Review
The amendment is open for 48 hours before any decision. During this window, any team member may comment with supporting evidence or counterarguments. Cross-constitution impacts are identified — an amendment to one constitution often requires changes to others. The Full System Design v2.0 is the tie-breaker for any conflict between constitutions.
Step 3 — Approve & Commit
Owner Approval + Version Bump
Only Maluleke Kurhula Success (KSDRILL SA owner) approves constitutional amendments. Approval is committed to system-design-template with: (1) version bump of the affected constitution, (2) updated changelog section, (3) updated Constitutional Order if the rule count changes, (4) cross-constitution updates if required. No amendment takes effect before committed to the repo.
Version bump rules: Minor bump (v3.0 → v3.1) for adding a rule, clarifying language, or adding stack-specific detail to an existing rule. Major bump (v3.x → v4.0) for removing a rule, changing the stack assignment, or restructuring a part. A version bump always includes an updated changelog entry with: what changed, why, and the effective date.

§ 12

Forbidden Patterns at Constitutional Level

Meta-Level Violations
⚠ CONSTITUTIONAL-LEVEL FORBIDDEN PATTERNS — THESE BREAK THE ENTIRE SYSTEM
FCO-01 — BUILDING OUT OF PHASE ORDER
Starting Phase 1 architecture work before Phase 0 constitutions are active and enforced. Most common violation.
✓ Fix: Complete Phase 0 validation loop before opening Phase 1 work.
FCO-02 — SYSTEM BUILT WITHOUT CONSTITUTIONAL REGISTRATION
Starting development of a new KSDRILL SA platform without registering it in this Constitutional Order document first.
✓ Fix: Register name, stack, build order slot, governing constitutions (T26, PF28).
FCO-03 — AMENDMENT WITHOUT OWNER APPROVAL
Changing any rule in any constitution without the documented 48-hour review and owner approval process.
✓ Fix: GitHub Issue → 48-hour review → Maluleke approval → commit with version bump.
FCO-04 — PARALLEL PLATFORM DEVELOPMENT
Beginning development of a second KSDRILL SA system before the first system's v1 has shipped to production.
✓ Fix: Sequential build order is locked. No parallel platform work (PF3, T1).
FCO-05 — STACK CHANGE MID-BUILD
Switching or adding a framework to a system mid-build because a feature "requires it."
✓ Fix: Stack assignment is immutable once build begins. Features fit the stack (T4, PF12).
FCO-06 — CONSTITUTION APPLIED OUT OF ORDER
Applying Phase 3 (Product) decisions before Phase 1 (Architecture) is fully established and validated.
✓ Fix: The Golden Rule — constitutions in the order the system would fail without them.
FCO-07 — SYSTEM TOTAL FIGURE CHANGED WITHOUT CO UPDATE
Changing rule counts in individual constitutions without updating the Constitutional Order register and running total.
✓ Fix: CO is the canonical source. Update §4 register on every rule count change.
FCO-08 — GROWTHCORE WORK USING KSDRILL CONSTITUTIONS WITHOUT AUTHORISATION
Applying KSDRILL SA constitutional frameworks to GrowthCore Solutions client projects without explicit written authorisation.
✓ Fix: Entities are separate. Frameworks are not shared without authorisation (PF6, T15).
