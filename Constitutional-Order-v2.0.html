§ 02

The Golden Rule — Refined

Priority Matrix
The Rule: Build constitutions in the order your system would fail without them.
The Refinement: Validate with code. Refine. Then lock. Each constitution answers three questions:
1. What breaks if I don't have this?  ·  2. What code must I write to validate this?  ·  3. When can this be locked permanently?
Priority Question Constitution Validation Required
P0 Without this, can the team function? Team & Process First retrospective completed
P0 Without this, can code be consistent? Code Quality First PR merged following these rules
P1 Without this, can the system exist? Backend First API endpoint working
P1 ⭐ Without this, can we trust the code? Testing Strategy First test passes
P1 Without this, can users exist? Auth Domain Login flow working
P1 Without this, can users interact? Frontend UI renders with real data
P1 Without this, can data be trusted? Database Schema survives Auth build
P2 Without this, can we deploy safely? Infrastructure First deployment succeeds
P2 Without this, can we handle failure? Incident Response First simulated incident
P3 Without this, can we build the right things? Product & Feature First feature ships

Amendment Protocol

NEW — Added to Constitution #1
Constitutions are LOCKED but not RIGID. Amendments follow a defined process. Three tracks exist based on urgency and impact.
Micro-Review — Every 2 Weeks
1
Team member identifies friction in a locked rule
2
Document: What rule? What friction? Proposed change?
3
Team votes (simple majority)
4
If approved: Rule amended, version incremented (v2.0 → v2.1)
5
Amendment logged in CHANGELOG.md
Quarterly Review — Every 90 Days
1
Full constitution audit across all 10 documents
2
Remove obsolete rules that no longer apply
3
Add rules based on production incidents & learnings
4
Version major increment (v2.0 → v3.0)

Forbidden Order Patterns v2.0

Never Do These
CONSTITUTIONAL ORDER FORBIDDEN PATTERNS — COF01 through COF10
COF01
Building Frontend before Backend
→ Backend first (#3 → #6)
COF02
Building Auth before Testing Strategy
→ Testing Strategy first (#4 → #5)
COF03
Locking Database before building Auth
→ Database is living document until Auth complete (#5 → #7)
COF04
Building Infrastructure before Auth works
→ Auth must deploy first (#5 → #8)
COF05
Skipping Validation Loops
→ Every Phase 1 constitution requires validation code
COF06
Skipping Micro-Reviews
→ 2-week checkpoints are mandatory, not optional
COF07
Building Product before all technical constitutions
→ Need reliable system before deciding features (#10 is last)
COF08
Treating constitutions as immutable
→ Amendment Protocol exists — use it. Constitutions must evolve.
COF09
Building in random order without dependency map
→ Follow dependency map in §8 exactly
COF10
Deploying to production before Phase 2 complete
→ Infrastructure + Incident Response required before prod
