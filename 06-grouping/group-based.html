§ 1 — Core Principles · Foundation of Group-Based Development
Golden Rule
"Build in the order your system would fail without them."
Key Constraints
  • Never Group N → Group N+1 imports
  • Never Skip groups
  • Never Exceed file limits
  • Always Complete before next
§ 1 / 5 PRINCIPLES Core Principles The Foundation of Group-Based Development
i
Constitutional Reference: These principles extend Frontend Constitution Rules 33–38 and Backend Constitution B19–B23. They apply to ALL systems built under the KSDRILL SA governance framework.
PrincipleDescriptionRule Reference
Sequential DependencyGroup N cannot depend on Group N+1. Forward references are FORBIDDEN. Group 1 must be complete before Group 2 starts.SD1
Fixed Size LimitsEach group has a maximum file count. Group 1: ≤15 files. Groups 2+: ≤10 files per group. Exceeding requires splitting or deferring.Rules 33-35
Adaptive Group CountNumber of groups = f(system complexity). Simple MVP = 2 groups total. Enterprise = 5+ groups. Add groups as complexity grows.Rule 36
v1 vs v2 SeparationGroups 1-2 are v1 (MVP). Groups 3+ are v2+ (placeholders with // TODO: v2+). Never build v2 features in v1.Rule 39
Group Completion GateA group is NOT complete until ALL files are implemented, tested, reviewed, and documentation is updated. No partial groups.SD3-SD4
!
Critical: Violation of any core principle in production code requires immediate rollback and constitution review. These are not guidelines — they are hard rules enforced by CI and code review.

Login, register, logout, session management, user profile. Every protected route depends on this group.

First core feature that delivers primary platform value. Must pass 5 gate questions before development.
Pages (3) Components (4) Services (2) Models (1)

Group 4: Secondary Feature ≤10 files
Second core feature (if MVP requires). Built only if primary feature validation succeeds.
Pages (3) Components (4) Services (2) Models (1)
Dependencies: Groups 1-3 · v1: Conditional
Group 5+: Future Features ≤10 files each
Features deferred to v2 or later. Only placeholders with // TODO: v2+ comments in v1.
Placeholder only No implementation
Dependencies: All previous groups · v1: No (placeholders only)
§ 3 — Sequential Dependency Rules · No Forward References · No Circular Dependencies
Allowed Imports
  • G1 None (standalone)
  • G2 G1 only
  • G3 G1, G2 only
  • G4 G1, G2, G3 only
  • G5+ All previous groups
Forbidden Imports
  • ✗ G1 → G2+ (reverse)
  • ✗ G2 → G3+ (forward)
  • ✗ Any circular
§ 3 / 4 RULES Sequential Dependency Rules Strict Hierarchy · No Exceptions
SD1 — No Forward References
// ✅ CORRECT: Group 2 importing from Group 1
import { AuthService } from '../../../group-1-core/core/auth.service';

// ❌ FORBIDDEN: Group 1 importing from Group 2
import { LoginPage } from '../../../group-2-auth/pages/login.page';
SD2 — No Cross-Group Imports Beyond Direct Dependency
// ✅ CORRECT: Group 3 importing from Group 2 (allowed)
import { AuthGuard } from '../../../group-2-auth/guards/auth.guard';

// ❌ FORBIDDEN: Group 3 importing from Group 4 (forward reference)
import { SettingsPage } from '../../../group-4-settings/pages/settings.page';
!
Critical Rule: Group 1 MUST be COMPLETE before Group 2 starts. Group 2 MUST be COMPLETE before Group 3 starts. NO forward references from Group 1 to Group 3. NO skipping groups. This is non-negotiable.

§ 5 — Group Lifecycle · From Draft to Archived
Status Meanings

  • Review Awaiting approval
  • Locked Complete, frozen
  • Archived Deprecated

→
IN PROGRESS
Implement · Test · Document
→
REVIEW
Code review · Verify tests
→
LOCKED
Complete · No changes w/o approval
→
ARCHIVED

§ 7 / 4 RULES Import & Export Rules Barrel Exports · No Deep Paths
group-1-core/index.ts — Barrel Export
export * from './layouts/main-layout/main-layout.component';
export * from './core/api-client.service';
export * from './core/auth.service';
export * from './ui/button/button.component';
Correct vs Forbidden Imports
// ✅ CORRECT: Import from index, not deep paths
import { AuthService } from '../../../group-1-core';

// ❌ FORBIDDEN: Deep path import (bypasses barrel)
import { AuthService } from '../../../group-1-core/core/auth.service';
!
CI Enforcement: ESLint rules no-restricted-imports and import/no-internal-modules enforce barrel exports. Deep imports outside allowed paths cause CI failures.

§ 8 / 2 GATES Group Transition Checklists Before Starting · After Completing
i
Pre-Group N Checklist — Before Starting
Pre-Group Checklist
### Dependencies
- [ ] Group N-1 is LOCKED
- [ ] All tests for Group N-1 are passing
- [ ] No open bugs in Group N-1
- [ ] Documentation for Group N-1 is complete

### Planning
- [ ] Group N file list defined (≤ max files)
- [ ] Estimated time per file documented
- [ ] Dependencies on previous groups mapped
- [ ] No forward references to Group N+1

### Gate Questions (for v1 groups beyond Group 1-2)
- [ ] G1: Serves v1 core need?
- [ ] G2: Can validate without it?
- [ ] G3: Can build in 2-4 weeks total?
- [ ] G4: Single clear success metric?
- [ ] G5: Removable without breaking system?
i
Post-Group N Checklist — After Completing
Post-Group Checklist
### Implementation
- [ ] All files created (≤ max files)
- [ ] All tests written and passing
- [ ] Documentation updated
- [ ] No linting errors
- [ ] No TypeScript errors

### Review
- [ ] Code review completed
- [ ] All review comments addressed
- [ ] Tests reviewed

### Lock
- [ ] Group status changed to LOCKED
- [ ] CHANGELOG updated
- [ ] Tagged with group version

### Next Group Ready
- [ ] Group N+1 can now start
§ 9 — Forbidden Patterns · Violation = Build Failure
⚠ FORBIDDEN PATTERNS — 10 PATTERNS — VIOLATION = BUILD FAILURE
FP01 — GROUP 2 IMPORTING FROM GROUP 3
Forward reference violates sequential dependency.
✓ Fix: Restructure, move shared logic to lower group.
FP02 — GROUP 1 HAVING >15 FILES
Scope creep, core foundation too large.
✓ Fix: Split into sub-modules or defer to Group 2.
FP03 — GROUP 2 HAVING >10 FILES
Feature bloat, auth group too large.
✓ Fix: Defer non-auth features to Group 3+.
FP04 — BUILDING GROUP 3 BEFORE GROUP 1 COMPLETE
Missing core dependencies.
✓ Fix: Complete Group 1 first, then Group 2, then Group 3.
FP05 — BUILDING V2 FEATURES IN V1
MVP overbuilding, delays launch.
✓ Fix: Defer to v2, add placeholder with // TODO: v2+.
FP06 — GROUP 1 REFERENCING GROUP 2
Circular dependency, core depends on feature.
✓ Fix: Move shared logic to Group 1, keep Group 1 independent.
FP07 — SKIPPING GROUPS (1 → 3 DIRECTLY)
Missing dependencies, unstable build.
✓ Fix: Build sequentially — complete each group before next.
FP08 — MODIFYING LOCKED GROUP WITHOUT APPROVAL
Breaking changes to completed work.
✓ Fix: Formal change request, constitution review, version bump.
FP09 — NO TODO COMMENTS FOR V2+ GROUPS
Undocumented future work, lost requirements.
✓ Fix: Add // TODO: v2+ — description to all placeholder files.
FP10 — CROSS-GROUP CIRCULAR IMPORTS
Unmaintainable dependency graph.
✓ Fix: Use barrel exports, enforce import rules with ESLint.
§ 10 — MVP vs Full System · Application Scenarios
§ 10 / SCENARIOS MVP vs Full System Simple · Standard · Enterprise
i
Simple MVP (2 Groups Total) — ≤25 files total. Group 1 (Core) + Group 2 (Auth + 1 core feature). Ship fast, validate, then add groups.
i
Standard System (3-4 Groups Total) — ≤45 files total. Group 1 (Core) + Group 2 (Auth) + Groups 3-4 (Primary + Secondary features). Typical for most production platforms.
i
Complex Enterprise System (5+ Groups Total) — ≤15 + (N × 10) files. Group 1 (Core) + Group 2 (Auth) + Groups 3-5+ (multiple features). Placeholders for v2+ features marked // TODO: v2+.
