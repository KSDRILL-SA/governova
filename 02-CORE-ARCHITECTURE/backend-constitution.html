PART 1 / B1–B6 Architecture & Boundaries 5 Critical · 1 High · Stack-differentiated
B1Service Responsibility BoundaryCritical
BOTH STACKS

FastAPI handles AI, predictions, RAG, and agents on all stacks. Next.js API Routes handle auth, CRUD, payments, and orchestration on the Next.js stack. On the Angular stack, FastAPI handles everything — auth, CRUD, AI, and domain logic. Never put AI calls in Next.js API routes or CRUD logic in the Next.js-stack FastAPI service.

Next.js Stack
Next.js owns: auth, CRUD, payments, orchestration. FastAPI owns: AI/RAG/predictions only. Strict boundary — never cross.
Angular Stack
FastAPI owns everything: auth, CRUD, AI, domain logic. Angular is frontend only. FastAPI is the entire backend.
B2Single Gateway Principle — Next.js Stack OnlyCritical
NEXT.JS STACK ONLY

On Next.js systems, the browser NEVER calls FastAPI directly. All requests proxy through Next.js API Routes. FastAPI is internal-only, inaccessible from the public internet, protected by X-Internal-API-Key.

!
Angular stack exception: Angular browsers call FastAPI directly via JWT-authenticated REST. B2 does not apply to FundsLink or Reserve Bank. Angular → FastAPI is the intended and correct pattern on those systems.
Enforcement (Next.js)
CORS config blocks direct FastAPI access + network policy
Exception (Next.js)
WebSocket /ws/chat only — SyncUp v1
B3FastAPI Internal-Only — Next.js StackCritical
NEXT.JS STACK ONLY

On Next.js systems, FastAPI endpoints are internal-only. They require X-Internal-API-Key header from Next.js and are never exposed to the public internet. On Angular systems, FastAPI endpoints are public-facing with JWT auth.

B4FastAPI — No PostgreSQL Writes via Next.js StackCritical
NEXT.JS STACK ONLY

On Next.js systems, the AI FastAPI service has NO database writes to PostgreSQL. State changes trigger a webhook back to Next.js. FastAPI reads ChromaDB only.

❌ Violation (Next.js stack)
# FastAPI AI service writing to Postgres
db.execute("INSERT INTO users ...")
✅ Correct (Next.js stack)
# FastAPI calls webhook back to Next.js
await httpx_post("/api/internal/webhook/...")
+
Angular stack (FundsLink, Reserve Bank): FastAPI IS the primary backend and has full read/write access to PostgreSQL and MongoDB. This is the correct architecture — not a violation. B4 does not apply to Angular systems.
B5Every FastAPI Endpoint Has a Corresponding Proxy — Next.js StackHigh
NEXT.JS STACK ONLY

On Next.js systems, every FastAPI endpoint must have a corresponding Next.js API route that proxies it. Both must be documented in the OpenAPI contract. Angular systems call FastAPI directly — no proxy needed.

B6One-Way Communication — No Circular CallsCritical
BOTH STACKS

Service communication is strictly one-way. Next.js stack: Next.js → FastAPI only; FastAPI may call one Next.js webhook (one-way, no response expected). Angular stack: Angular → FastAPI → DB only. No circular references, no service calling the service that called it.

PART 2 / B7–B12 API Contract 5 Critical · 1 High · Both Stacks
B7OpenAPI First Principle — Contract Before CodeCritical
BOTH STACKS

The OpenAPI 3.0 contract MUST exist and be approved before ANY endpoint code is written. PR shows OpenAPI changes BEFORE implementation changes. CI fails if contract is missing, incomplete, or mismatched with implementation. Both Next.js and FastAPI (Angular stack) maintain their own OpenAPI contracts.

B8Standard Response Format — ApiResponse<T> on All EndpointsCritical
BOTH STACKS

ALL responses from ALL endpoints follow the ApiResponse<T> format. No exceptions. This applies to Next.js API routes, the Angular-stack FastAPI, and the Next.js-stack FastAPI AI service.

types/api.ts · shared across both stacks
type ApiResponse<T> = {
  success: boolean;
  data: T | null;
  error: {
    code: string;
    message: string;
    field?: string;  // validation errors only
  } | null;
  meta?: { pagination?: { page: number; limit: number; total: number; pages: number; }; };
}

BOTH STACKS

Error codes are limited to the v1 set. New codes require a documented cross-constitution review and defer to v2. The same 9 error codes are used identically by both the Next.js stack and the Angular/FastAPI stack.

B10Frontend Type Generation from OpenAPI — Never ManualCritical
BOTH STACKS

Frontend validation types are always generated from the OpenAPI contract. Manual schema writing is forbidden. Pre-commit hook enforces this on both repos.

Next.js Stack
Zod schemas generated via openapi-zod-client. Output to lib/api/generated/. Pre-commit hook: fails if generated schemas are out of sync with OpenAPI contract.
Angular Stack
TypeScript interfaces generated via openapi-typescript. Output to src/api/generated/. Angular validators must match Pydantic shapes — verified by integration test.
B11Validation Parity — Frontend and Backend Must MatchCritical
BOTH STACKS

Every field validated on the frontend must be validated identically on the backend. If email is required on the frontend, it is required on the backend. Mismatches are a critical violation caught by contract test in CI.

Next.js Stack
Next.js Zod ↔ FastAPI Pydantic parity. Both generated from OpenAPI. Mismatch = contract test failure.
Angular Stack
Angular Reactive Form validators ↔ FastAPI Pydantic models parity. Both derived from OpenAPI contract. Angular TypeScript types auto-generated.
B12Error Transformation — Raw Errors Never Reach the ClientCritical
BOTH STACKS

Raw Pydantic validation errors, database errors, and stack traces must never reach the client. All errors are caught at the service boundary and transformed to ApiResponse<T> format with the appropriate error code from the v1 set.

Next.js Stack
Next.js API routes wrap FastAPI proxy calls in try/catch and call formatApiError(err) before returning. Raw FastAPI 422s never reach Angular/browser.
Angular Stack
FastAPI global exception handler transforms all errors. Custom HTTPException handler maps to ApiResponse format. Angular HTTP interceptor handles 4xx/5xx consistently.

PART 3 / B13–B18 Database — Relational 4 Critical · 2 High · Both Stacks
B13Prisma as Source of Truth for Relational DataCritical
BOTH STACKS — PostgreSQL

The Prisma schema is the single source of truth for all relational data structures. All migrations run through Prisma. Raw SQL is allowed ONLY for complex aggregates or recursive CTEs — every such query must include a comment explaining why Prisma ORM is insufficient.

B14Required Table Fields — id, created_at, updated_at on Every TableHigh
BOTH STACKS — PostgreSQL

Every PostgreSQL table must have: id (UUID/cuid), created_at (@default(now())), updated_at (@updatedAt). Enforced by Prisma schema lint in CI. Tables missing these fields fail the build.

B15aNext.js Stack — AI FastAPI Has No PostgreSQL AccessCritical
NEXT.JS STACK ONLY

On Next.js systems (Maphophe, SyncUp), the AI FastAPI service has NO access to PostgreSQL. It reads ChromaDB only. All state changes that need to persist to Postgres are sent back to Next.js via an internal webhook. Network policy blocks direct PostgreSQL connection from the FastAPI container.

!
This is the corrected rule (was B15 in v2.2). The old B15 said "FastAPI never touches PostgreSQL" with no qualification. This caused confusion on Angular systems where FastAPI IS the primary backend and must access PostgreSQL. B15 is now split into B15a (Next.js) and B15b (Angular).
B15bAngular Stack — FastAPI Is the Primary Database OwnerCritical
ANGULAR STACK ONLY

On Angular systems (FundsLink, Reserve Bank), FastAPI has full read/write access to both PostgreSQL (via Prisma or SQLAlchemy) and MongoDB (via Mongoose). FastAPI is the primary and only backend — it handles all database operations. There is no separate "orchestration layer" above it.

MongoDB access
Full read/write via Mongoose (B47–B52)
ChromaDB access
Read-only for RAG — FundsLink only (F13–F14)
B16Database Separation — Relational vs Vector vs DocumentCritical
BOTH STACKS

Separate data by type and purpose. PostgreSQL stores structured relational data (users, transactions, governance records). ChromaDB stores vector embeddings (RAG context, document similarity). MongoDB stores flexible document data (AI-generated outputs, dynamic schemas, logs — Angular stack only). Never store embeddings in PostgreSQL, never store relational data in MongoDB.

PostgreSQL
Users · transactions · votes · applications · sessions
MongoDB
AI outputs · dynamic content · logs · flexible schemas
ChromaDB
Embeddings · RAG context · document similarity only
B17Cross-Database Sync PatternHigh
BOTH STACKS

When a change to PostgreSQL data must be reflected in ChromaDB or MongoDB (e.g., user profile update that affects RAG context), the sync must be explicit and tested. Integration tests must verify cross-database sync correctness. No silent sync — every cross-database write is logged.

Next.js Stack
Next.js API → FastAPI webhook → ChromaDB update. Integration test verifies sync on each deploy.
Angular Stack
FastAPI service layer coordinates Postgres + MongoDB writes in a single transaction-aware operation. Sync failures trigger a rollback and error log.
B18Selective Field Selection — No SELECT * on Any QueryCritical
BOTH STACKS — PostgreSQL

All Prisma queries use explicit select to return only the fields needed. Never use findMany() or findFirst() without a select clause. Never expose password_hash, reset_token, refresh_token, or deleted_at.

❌ Exposes sensitive fields
prisma.user.findMany() // no select
✅ Explicit safe fields
prisma.user.findMany({
  select: { id: true, email: true, name: true }
})

B47Mongoose as the ODM — All MongoDB Access Via SchemasNew · High
ANGULAR STACK ONLY

All MongoDB access must go through Mongoose schemas and models. Direct MongoDB driver calls without a Mongoose schema are forbidden. Every collection must have a defined Mongoose schema before any document is written.

models/scholarship-match.model.py (Mongoose-equivalent via Motor/Beanie)
# Python FastAPI: use Beanie ODM (Pydantic + Motor)
class ScholarshipMatch(Document):
    student_id: str                 # ref to PostgreSQL user id
    match_score: float
    matched_at: datetime
    ai_reasoning: str              # AI-generated content
    created_at: datetime = Field(default_factory=datetime.utcnow)
    deleted_at: Optional[datetime] = None  # B52: soft delete

    class Settings:
        name = "scholarship_matches"
        use_state_management = True
B48MongoDB for Document Data Only — Never for Financial TransactionsNew · Critical
ANGULAR STACK ONLY

MongoDB is used exclusively for document data: AI-generated content, dynamic schemas, application logs, and feature-rich data that evolves without migration overhead. Financial transactions (Reserve Bank deposits, interest calculations, balances), authentication data, and any data requiring ACID guarantees must stay in PostgreSQL.

❌ Never in MongoDB
transactions collection {
  amount: 5000,        // financial data
  balance: 12000,      // balance
  interest_rate: 0.05  // calculated
}
✅ Correct in MongoDB
scholarship_matches collection {
  ai_reasoning: "...", // AI output
  match_score: 0.87,
  dynamic_tags: [...]  // flexible schema
}
B49MongoDB Timestamps — timestamps: true on All SchemasNew · High
ANGULAR STACK ONLY

All Mongoose/Beanie schemas must enable automatic timestamps. This adds createdAt and updatedAt fields automatically. No manual timestamp management. Every document must be traceable by creation and modification time.

B50Cross-Database References Use PostgreSQL IDs — Not ObjectIDsNew · Critical
ANGULAR STACK ONLY

When a MongoDB document references a user, record, or entity that exists in PostgreSQL, the reference field stores the PostgreSQL cuid string — NOT a MongoDB ObjectID. This maintains the PostgreSQL record as the system of record. MongoDB documents are subordinate to PostgreSQL entities.

Reference field naming
student_id: str — stores the Prisma cuid
Source of truth
PostgreSQL record — MongoDB document is a child
B51MongoDB Indexes — Define Indexes Explicitly, No Implicit ScanningNew · High
ANGULAR STACK ONLY

All MongoDB query fields must have explicit indexes defined in the schema. Never query a collection field without an index in production. Define indexes in the Mongoose/Beanie schema definition — not in ad-hoc migration scripts. CI validates that query fields have corresponding index definitions.

B52Soft Delete on MongoDB — deletedAt Field, Never Hard DeleteNew · High
ANGULAR STACK ONLY

MongoDB documents follow the same soft delete pattern as PostgreSQL (B39). Set deletedAt timestamp instead of removing documents. All queries must filter { deletedAt: null } by default. A Mongoose middleware plugin enforces this automatically on all schemas.

PART 9 / F1–F15 FastAPI AI Rules AI functions on both stacks · LangChain replaces OpenAI
F1AI Models Load Once at Startup — Under 5 SecondsCritical
BOTH STACKS — AI Functions

AI models and LangChain chain objects load once at FastAPI startup, stored as application state. Never load models per-request. Startup time must be under 5 seconds. Models unload after 30 minutes of idle to reclaim memory.

F3Concurrency Limiting — Semaphore at cpu_count × 2Critical
BOTH STACKS — AI Functions

AI inference is gated by a semaphore set to cpu_count × 2. Requests that exceed the semaphore queue with a 30-second timeout, then return AI_SERVICE_UNAVAILABLE. Never allow unbounded concurrent AI inference.

F6async def for I/O — def for CPU — Never MixCritical
BOTH STACKS — FastAPI

FastAPI route handlers that perform I/O (DB reads, HTTP calls, ChromaDB queries) must use async def. CPU-bound operations (inference, embeddings, computations) use def and are wrapped in asyncio.to_thread(). Never block the async event loop with CPU work.

F11Token Budget Guard — Reject Requests Exceeding BudgetHigh
BOTH STACKS — AI Functions

Count tokens before sending to LangChain or any LLM. If the input exceeds the configured token budget, reject with VALIDATION_ERROR and a clear message indicating the limit. Never silently truncate — always tell the caller what happened.

F12LangChain Response Caching — 1 Hour TTLHigh
BOTH STACKS — AI Functions

Identical LangChain prompts with identical context must be cached for 1 hour using a Redis-backed LangChain cache. Never make a duplicate LLM API call when the response can be served from cache. Cache key includes: prompt hash + context hash + model version.

i
Updated from v2.2: "OpenAI Cache" → "LangChain response cache". LangChain's built-in RedisCache abstraction handles this — do not implement a custom cache layer.
F13ChromaDB — Separate Container, Read-Only for AI ServiceCritical
ANGULAR STACK — FundsLink Only

ChromaDB runs in its own container, separate from FastAPI. The AI service has read-only access to ChromaDB for RAG queries. Write access (embedding ingestion) is a separate admin-only process. Never co-locate ChromaDB with FastAPI in the same container.

F14Similarity Threshold — Minimum 0.7, Never Return BelowCritical
ANGULAR STACK — FundsLink Only

ChromaDB similarity searches must have a minimum score threshold of 0.7. Results below this score are discarded — never returned to the user. If no results meet the threshold, return an empty result set with a graceful "no matches found" response, not a degraded low-confidence answer.

docker-compose up must start the full local development environment in one command: all services (Next.js or Angular + FastAPI), PostgreSQL, MongoDB (Angular stack), Redis (where applicable), and ChromaDB (FundsLink). A new developer must be able to run the full stack with a single command after cloning the repo.

B58Health Checks — All Services Expose /health Before TrafficNew · High
BOTH STACKS

Every service exposes a /health endpoint that returns: service status, database connectivity status, and dependency health (Redis, ChromaDB where applicable). Railway and Vercel use this endpoint to gate traffic. A service that fails its health check does not receive traffic.

§ Part 11 — Cross-Constitution Governance (B46)
B46Cross-Constitution Governance — Backend Review Required on Frontend Contract ChangesCritical
ALL 10 CONSTITUTIONS

Any PR that changes the OpenAPI contract, ApiResponse shape, error codes, rate limits, or auth strategy must include a Backend-Review-Required: Yes label. CI fails without this label on cross-constitution changes. This governance rule connects all 10 constitutions — a change in any one may require review of multiple others. The Constitutional Order v2.0 defines the full review chain.

§ Annex A — Forbidden Patterns (FP01–FP22)
⚠ FORBIDDEN PATTERNS — VIOLATION = BUILD FAILURE · BOTH STACKS UNLESS MARKED
FP01 — OPENAI DIRECT FROM NEXT.JS API ROUTES
Calling OpenAI or LangChain APIs directly from Next.js API routes. All AI goes through FastAPI.
✓ Fix: Proxy to FastAPI AI service (B1, B5).
FP02 — FASTAPI TOUCHING POSTGRES (NEXT.JS STACK)
The AI FastAPI service on the Next.js stack making any PostgreSQL read or write. Network policy blocks this.
✓ Fix: FastAPI calls Next.js webhook (B4, B15a).
FP03 — MANUAL VALIDATION SCHEMAS
Hand-writing Zod schemas or Angular validators instead of generating from the OpenAPI contract.
✓ Fix: Generate from OpenAPI (B10).
FP04 — SELECT * IN PRISMA QUERIES
Using findMany() or findFirst() without an explicit select clause.
✓ Fix: Always use explicit select (B18).
FP05 — RAW ERROR EXPOSED TO CLIENT
Pydantic 422 errors, stack traces, or database errors reaching the Angular/browser client.
✓ Fix: Transform all errors to ApiResponse<T> (B12).
FP06 — NO OPENAPI CONTRACT BEFORE CODE
Writing endpoint implementation before the OpenAPI 3.0 contract is complete and approved.
✓ Fix: OpenAPI first, always (B7).
FP07 — HARD DELETE IN PRODUCTION
Deleting any PostgreSQL row or MongoDB document permanently from production without admin process.
✓ Fix: Soft delete with deleted_at (B39, B52).
FP08 — BLOCKING ASYNC EVENT LOOP
Running CPU-bound inference or computation inside an async def FastAPI handler.
✓ Fix: Use asyncio.to_thread() for CPU work (F6).
FP09 — SIMILARITY BELOW 0.7 RETURNED
Returning ChromaDB results with a similarity score below 0.7 to users.
✓ Fix: Filter at threshold, return empty if none qualify (F14).
FP10 — DIRECT OPENAI API CALLS
Calling the OpenAI API directly without going through LangChain abstraction layer.
✓ Fix: All LLM calls via LangChain chains (F12).
FP11 — SECRETS IN COMMITTED FILES
Any API key, connection string, or JWT secret in any committed file, including .env.
✓ Fix: Railway Secrets / Vercel Env / .env.example only (B56).
FP12 — FASTAPI ON VERCEL [ANGULAR STACK]
Attempting to deploy a Python FastAPI service to Vercel serverless functions.
✓ Fix: FastAPI deploys to Railway (B53).
FP13 — FINANCIAL DATA IN MONGODB [ANGULAR STACK]
Storing Reserve Bank transaction amounts, balances, or interest data in MongoDB documents.
✓ Fix: Financial data belongs in PostgreSQL (B48).
FP14 — MONGODB WITHOUT MONGOOSE SCHEMA [ANGULAR STACK]
Direct MongoDB driver calls without a Beanie/Mongoose schema definition.
✓ Fix: All MongoDB access via defined schemas (B47).
FP15 — ANGULAR TREATED AS NEXT.JS STACK
Applying B2 (Single Gateway), B3 (Internal-only), or B4 (No Postgres writes) to FundsLink or Reserve Bank.
✓ Fix: Angular rules: B15b applies — FastAPI is the primary backend.
FP16 — UNSEQUENCED DEPLOY ON BREAKING CHANGES
Deploying FastAPI and Angular simultaneously on releases that change API contracts.
✓ Fix: FastAPI first, Angular second (B54).
FP17 — MIGRATIONS SKIPPED ON DEPLOY
Starting a FastAPI or Next.js service without running prisma migrate deploy first.
✓ Fix: Migrations are the first command in every deploy (B55).
FP18 — UNBOUNDED AI CONCURRENCY
Running AI inference without a semaphore concurrency limit.
✓ Fix: Semaphore at cpu_count × 2 (F3).
FP19 — CROSS-DB REFERENCE VIA OBJECTID [ANGULAR STACK]
MongoDB documents referencing PostgreSQL entities using a MongoDB ObjectID instead of a Prisma cuid.
✓ Fix: Use PostgreSQL cuid as the reference field value (B50).
FP20 — NO AUDIT LOG ON STATE CHANGES
Any state change (user update, transaction, vote) that is not recorded in the audit log.
✓ Fix: All state changes logged in AuditLog table (B38).
FP21 — NEW ERROR CODE WITHOUT APPROVAL
Adding a 10th error code to the v1 set without a documented cross-constitution review.
✓ Fix: 9 error codes only in v1, defer to v2 (B9).
FP22 — NO HEALTH CHECK ENDPOINT
Any service launched without a /health endpoint that checks database and dependency connectivity.
✓ Fix: Every service exposes /health before traffic (B58).
