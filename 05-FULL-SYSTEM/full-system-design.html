§ 01

System Architecture — Dual Stack Topology

Structural
Critical Distinction: KSDRILL SA operates two parallel frontend+backend stacks. Next.js systems (Maphophe, SyncUp) use integrated API routes and NextAuth. Angular systems (FundsLink, Reserve Bank) use a dedicated FastAPI backend with JWT auth. The rules governing each stack differ — always verify which stack a rule applies to.
NEXT.JS STACK Maphophe · SyncUp
Systems: Maphophe Community System · SyncUp Creator Platform
Pattern: Content-driven · SEO-critical · Full-stack unified
Frontend: Next.js App Router · React · TypeScript · Tailwind + Custom CSS · shadcn/ui
Auth: NextAuth.js — session management, HTTP-only cookies
Backend: Next.js API Routes (built-in, no separate server)
Database: PostgreSQL via Prisma ORM
Jobs: BullMQ + Redis (SyncUp: negotiation timers · drop scheduling)
Browser
↓ HTTPS (Rule 1–10 · 44×44px · WCAG AA)
Next.js Frontend (React · Tailwind · SSR/SSG)
↓ ALL requests through /api/v1/* (B2 — Single Gateway)
Next.js API Routes ◄── NextAuth.js
↓ B26 Rate limit · B11 Zod validate · B37 RBAC · B38 Audit
Service Layer
↓ Prisma ORM (B13 — source of truth)
PostgreSQL + Redis/BullMQ (where applicable)
ANGULAR + FASTAPI STACK FundsLink · Reserve Bank
Systems: FundsLink Academy · KSDRILL Reserve Bank
Pattern: Enterprise-grade · AI-powered · Precision-critical · Dedicated backend
Frontend: Angular · TypeScript · Tailwind + Custom CSS · shadcn/ui · Reactive Forms
Auth: JWT — stateless token auth (Angular intercepts, FastAPI validates)
Backend: FastAPI (Python) — dedicated server, separate deployment
Database (Relational): PostgreSQL via Prisma ORM
Database (Document): MongoDB + Mongoose (flexible/AI-generated data)
AI Engine: LangChain · ChromaDB — FundsLink only
Jobs: BullMQ + Redis — Reserve Bank (deposit schedules · interest cron)
Browser
↓ HTTPS (Angular Reactive Forms · strict TypeScript)
Angular Frontend (TypeScript · Tailwind · shadcn/ui)
↓ HTTP REST with JWT Authorization header
FastAPI Backend (Python) ◄── JWT Auth Middleware
↓ splits into two paths
Prisma ORM → PostgreSQL  |  LangChain → ChromaDB
↓ BullMQ + Redis (Reserve Bank scheduled jobs)
✕ Angular → Next.js API (wrong stack, never cross)
✕ FastAPI → direct PostgreSQL writes from AI layer
Rule B2 — Single Gateway (Next.js systems only): In Next.js systems, the browser never calls FastAPI directly. Angular systems communicate directly with FastAPI via JWT-authenticated REST. FastAPI in Angular systems handles both AI operations AND standard CRUD through the same service layer, unlike Next.js systems where FastAPI is AI-only.

Deployment Order — Stack-Specific Strategy

Both Stacks
Next.js Systems — Unified Deployment VERCEL
1
Vercel auto-deploys on main branch push
2
Frontend + API routes deploy together (same codebase)
3
DB migrations run via Prisma on deploy hook
One-click · Zero backend coordination needed for Next.js stack
Angular + FastAPI Systems — Coordinated Deploy RAILWAY + VERCEL
1
FastAPI deploys first (Railway) — new endpoints ready
2
Angular deploys (Vercel) — calls new FastAPI endpoints
3
DB migrations (Prisma) run before FastAPI starts
Risk: Angular briefly calls old FastAPI during deploy window
Use Railway zero-downtime deploy + Angular version guards
Removing an Endpoint SAFE
1
Frontend deploys first (stops calling endpoint)
2
Backend removes after 6-month deprecation (B44)
Frontend stops calling before backend removes — safe in both stacks
Breaking Response Shape Change SAFE VIA VERSIONING
1
Backend deploys /v2 endpoint with new shape
2
Frontend deploys (calls /v2) — both stacks
3
Backend deprecates /v1 with Sunset header (6 months)
Versioned API prevents breaking existing clients
