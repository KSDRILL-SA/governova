### The two defects the first run found, which review had not

Both are recorded because **the finding is more durable than the fix**.

1. **`DEFAULT_IGNORES` knew `tests/` and not `test/`.** Twenty of express's original
   twenty-one blocking findings were error-handling fixtures in `test/`, singular — the
   dominant convention across Node, Go and Ruby. Every one was code written deliberately
   to exercise the behaviour the rule looks for, which is exactly what that list exists to
   skip. **It was invisible for as long as the engine only ever scanned its own source
   tree**, because this repository keeps its tests in `scripts/tests/`. Fixed with
   `test/`, `__tests__/`, `spec/`, `specs/` — and guarded in *both* directions, because
   widening a skip list until a report looks clean is how a scanner stops scanning, and it
   would be invisible: the findings simply never appear.
2. **The heatmap counted a violation the report could not print.** The findings section
   knew only the reliable tier, so a probe violation showed as a number in the `violated`
   column beside the words "no findings". A number a report cannot explain is worse than
   one it does not show.

### Raised, deliberately not fixed — `#195` and `#196`

- **`#195` — a blocking rule cites the wrong anti-pattern of its own standard.**
  `AP-S2.18a` is *"raw **database** error message returned in the API response"*;
  `AP-S2.18b` is *"`error.message` or `error.stack` sent directly to the client"*. The
  regex implements 2.18b and is filed under 2.18a, so express's one true finding is
  reported under a description mentioning a database that is not there. The swap is
  **count-neutral** (36/498 either way, and `enforced_clean_standards` keys on the
  standard) but it changes the covered-anti-pattern *set*, so it is its own change.
- **`#196` — the violation-rate factor saturates.** `100 - 10·blocking - 3·advisory`,
  floored at zero, is a count with **no notion of density**: 34 advisory findings zero it
  whether the repository has 30 files or 30,000. On first contact it is usually the only
  assessable factor, so `pallets/click` — a mature, careful library — opens at 0/100 (F).
  **`onboard` now states how many factors the headline rests on, which is presentation and
  L3's. The §18.1 model is `C0 §8` and belongs to L4**, so it was left alone.

## §4 — Standing rules you must not violate

Each was established because the alternative was tried and failed. Rules 1–13 carry
forward from the superseded handoff unchanged; **14 and 15 are new this session.**

1. **A check that cannot determine an answer returns `unknown`, never `satisfied`.**
2. **A probe or rule must never grade against a rubric wider than the standard it cites.**
   Law first, check second, never the reverse. (`#195` is the narrower cousin: the right
   check filed under the wrong anti-pattern of the right standard.)
3. **Every regex quantifier is bounded**, and `scan_text` caps line length.
4. **Anything reaching a subprocess argument is validated as what it claims to be.**
5. **Errors never echo URLs or credentials.**
6. **Evidence must resolve *inside* the repository.**
7. **Every new rule needs a positive *and* a negative test.** The negative — a repository
   doing exactly what a repository is for — is the one that matters.
8. **Core and domain metrics never mix.**
9. **No AI references anywhere in the GitHub surface** (`S1.100`).
10. **One run of a non-deterministic backend is a sample, not a measurement.**
11. **A metric's definition is never silently widened.** Report alongside; never fold in.
12. **Before trusting a measurement, prove the thing being measured was actually asked.**
13. **A threshold must sit between two reachable scores, or it is not a threshold.**
14. **A number a report shows must be a number that report can explain.** The heatmap
    counted a probe violation the findings section had no way to print, so the reader saw
    a violated standard beside the words "no findings". Any total and its itemisation are
    one feature, not two, and a test now asserts every counted violation is reachable from
    something printable.
15. **A default that was only ever exercised against this repository has not been tested.**
    `DEFAULT_IGNORES` was correct for four tiers and 566 tests and wrong for most of the
    software industry, because Governova's own tests live in `scripts/tests/`. **The
    cheapest way to find this class of defect is to run the tool on somebody else's code
    once, early** — it cost one command and found two defects that no amount of reading
    had.

## §6 — Traps that will cost you an hour

1. **`mypy` must run from `scripts/`.**
2. **`ruff format` is *not* enforced in CI** — only `ruff check`. Do not "fix" formatting.
3. **Heredocs mangle regex escapes.** Use the Edit tool for regex changes.
4. **`platform/shared/types-py` is generated *and* committed.** Never hand-edit.
5. **The `compiled/constitution.json` checksum is content-only.**
6. **Two workspace members cannot share a name.**
7. **`enforce.yml` pins `version: source`.** Keep it.
8. **`Select-Object -First N` on a piped native command produces exit code 255.** A
   broken-pipe artifact, not a failure.
9. **`governova licences` must run through `uv run`.**
10. **`gh project item-add` can report success without adding the item.** It returned
    cleanly and `item-list` did not show the issue; a second identical call worked.
    **Always verify with `item-list`** — this is a stronger version of the known
    `gh issue edit --add-project` no-op.
11. **Adding standards moves every pinned count** across five test files.
12. **`✓`/`✗` no longer crash on cp1252** — `governova_console` handles it. Route any new
    surface through that module.
13. **Do not lower a coverage floor to make a test pass.**
14. **A semantic evaluation makes ~17 sequential calls per run and dies on any one
    failure.** A failed measurement is usually worth simply repeating.
15. **`GOVERNOVA_LLM_MAX_TOKENS` too low reads as a dead tier, not a small one.** Use 2048.
16. **Running from a source checkout, nothing is bundled.** `BUNDLED_INDEX` ships in the
    wheel, so `load_active_index` against a *foreign* directory finds no constitution and
    every consumer command dies before scanning anything. `onboard` handles this by asking
    the target first and falling back to the invocation's own context
    (`_onboard_index_path`); for anything else, set `GOVERNOVA_CONSTITUTION`.
17. **Rich eats `[project]`.** Any TOML or bracketed text printed through `console.print`
    with markup enabled loses its table headers — the proposed profile was briefly offered
    to reviewers as un-parseable TOML. Print it as `rich.text.Text`.
18. **A submodule shadows a same-named re-export.** `from governova_onboard.render import
    to_json` binds `render` on the package, overwriting a `render` function re-exported
    from elsewhere in `__init__`. The onboarding proposal renderer is called
    `render_profile` for exactly this reason.

## §9 — The pattern worth continuing

**The most valuable findings are still the ones where a gate caught its own author.** This
session added two, and one of them caught *the test rather than the code*: a case asserting
that `lib/test_helper_service.py` should be scanned turned out to be wrong about the
pre-existing ignore globs — the file genuinely looks like a test module. The right move was
to fix the test, not the list.

But the sharper lesson is narrower than "write gates":

**A default only ever exercised against this repository has not been tested.**
`DEFAULT_IGNORES` survived four detection tiers, 566 tests and every review, and was wrong
for most of the industry — because every one of those exercised it against a tree whose
tests live in `scripts/tests/`. **One run against a stranger's code found two defects in
under a minute.**

Stages 1 and 2 will build on the same detection surface. Point them at somebody else's
repository on the first day, not the last.
