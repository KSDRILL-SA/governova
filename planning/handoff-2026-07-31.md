## §3 — Standing rules you must not violate

Each was established because the alternative was tried and failed.

1. **A check that cannot determine an answer returns `unknown`, never `satisfied`.** This
   now spans four tiers — probes, the requirements analyser, the schema analyser, and the
   semantic tier all follow it.
2. **A probe or rule must never grade against a rubric wider than the standard it cites.**
   Amend the standard first. Law first, check second, never the reverse.
3. **Every regex quantifier is bounded**, and `scan_text` caps line length. A parameterised
   test times every rule against ten adversarial payloads; `test_schema.py` does the same
   for both schema parsers against eight.
4. **Anything reaching a subprocess argument is validated as what it claims to be.**
5. **Errors never echo URLs or credentials.** A test asserts an endpoint configured as
   `https://user:key@host` leaks neither on failure.
6. **Evidence must resolve *inside* the repository.**
7. **Every new rule needs a positive *and* a negative test.** The negative — a repository
   doing exactly what a repository is for — is the one that matters.
8. **Core and domain metrics never mix.**
9. **No AI references anywhere in the GitHub surface** — commits, PR/issue titles and
   bodies, branch names, co-authors, filenames. Human attribution only (`S1.100`).
10. **One run of a non-deterministic backend is a sample, not a measurement.** Measured
    variance on `gpt-oss:120b`: precision 60–100% across five passes over identical input.
    `governova semantic-eval --runs N` reports the spread and judges on the **worst** run,
    because a backend that gives two answers for the same code cannot be defended either
    time.
11. **A metric's definition is never silently widened.** When `mechanical_coverage_pct` was
    added, `coverage_pct` kept its exact original meaning so every historical reading of it
    stays true. Report alongside; never fold in.

### Workflow (`protocols/github-workflow.md`)

```
BRANCH  →  ISSUE  →  PR  →  MERGE
```

Branch first. Then an issue with **full metadata**: type, milestone (`Governova v2.0`),
project, labels, assignee (`Maluleke-KS`). Then a PR with `Closes #N` and the same
metadata. Squash-merge, delete the branch.

```bash
gh issue create --title "..." --body-file <file> --label enhancement \
  --milestone "Governova v2.0" --assignee Maluleke-KS
gh project item-add 2 --owner "@me" --url <issue url>     # `gh issue edit --add-project` silently no-ops
gh pr create --title "..." --body-file <file> --base main --head <branch> ...
gh pr checks <N> --watch --interval 15
gh pr merge <N> --squash --delete-branch
```

**Commit types (`S1.19`, C1 v1.5): `feat` `fix` `docs` `chore` `refactor` `test` `style`
`perf` `ci` `govern` `decision` — and nothing else.** `harden` was considered and refused;
one `harden:` commit remains a violation of record and the probe still reports it.

## §5 — Traps that will cost you an hour

1. **`mypy` must run from `scripts/`.**
2. **`ruff format` is *not* enforced in CI** — only `ruff check`. Do not "fix" formatting;
   you will produce a huge unrelated diff.
3. **Heredocs mangle regex escapes.** Use the Edit tool for regex changes.
4. **`platform/shared/types-py` is generated *and* committed.** Never hand-edit. Change
   `scripts/governova_compile/schema.py`, run `governova-codegen --skip-ts`, commit both.
5. **The `compiled/constitution.json` checksum is content-only.** If drift-check fails, you
   changed constitutional *content*.
6. **Two workspace members cannot share a name.** Root is `governova-workspace`; the
   publishable engine in `scripts/` is `governova`.
7. **`enforce.yml` pins `version: source`** so a PR is judged by the constitution the branch
   proposes. Keep it.
8. **`Select-Object -First N` on a piped native command produces exit code 255.** A
   broken-pipe artifact, not a failure.
9. **`governova licences` must run through `uv run`** — it classifies *installed
   distributions*.
10. **`gh issue edit --add-project` prints a URL and silently does nothing** for this
    project. Use `gh project item-add 2 --owner "@me" --url <url>` and verify with
    `gh project item-list 2 --owner "@me"`.
11. **Adding standards moves every pinned count.** `test_compile_and_validate.py`,
    `test_checks.py`, `test_mcp.py`, `test_report.py`, `test_codegen.py` all pin totals.
    They exist so a change of that size cannot land quietly — update them deliberately.
12. **`✓`/`✗` no longer crash on cp1252.** `governova_console` reconfigures stdout for
    every entrypoint. If you add a seventh surface, route it through that module — a test
    fails if you build a bare `Console()`.
13. **Do not lower a coverage floor to make a test pass.** `test_rule_coverage_floor` was
    rewritten, not relaxed, when corpus growth pushed the rule-only ratio down: the guard
    now asserts the rule set has not shrunk and *mechanical* reach has not fallen. Lowering
    a bar to accommodate growth is how a guard stops guarding.

### The one distinction that matters most

**Where the standards live** and **which repository is being governed** are different
questions.

- `resolve_repo_root()` — the **authoring** tree. Requires `constitution/`. Only
  `compile`/`validate`/`codegen` may use it.
- `resolve_target_root()` — the repository **under governance**. Git root, else cwd.
  **Never raises.**
- `load_active_index()` — precedence: explicit arg → `GOVERNOVA_CONSTITUTION` →
  working-tree `compiled/constitution.json` → bundled. **That precedence is load-bearing.**

### Two extension points added in Phase 2

Both exist because a second concrete case already existed — the line `AP-S1.107a` draws:

- `governova_requirements.register_reader` — `referenced` and `manifest` ship; ReqIF and
  tracker exporters land without touching core.
- `governova_requirements.register_rule` — seven grammar rules ship; house and
  regulator-specific rules are additions, not edits.

## §7 — Cutting a release

`governova` is on PyPI. v0.1.0 shipped via OIDC Trusted Publishing — **there is no API
token anywhere in this repository, and there must not be.**

```bash
# 1. Bump scripts/pyproject.toml  ->  [project] version = "0.2.0"
# 2. Merge through branch → issue → PR → merge.
# 3. Tag the merged commit on main:
git tag -a v0.2.0 -m "governova 0.2.0" && git push origin v0.2.0
```

A merge never publishes; only a `v*` tag does. **Never hand-build and hand-upload. The
gates are the release.**

> **There is substantial unreleased work on `main`** — the whole of Phase 2. A v0.2.0 is
> due, and `SCHEMA_VERSION` has moved 1.1.0 → 1.2.0, so `governova-types` republishes with
> it.
