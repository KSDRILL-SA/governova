## §3 — Standing rules you must not violate

These were each established because the alternative was tried and failed. `ADR-006`
records the security ones.

1. **A check that cannot determine an answer returns `unknown`, never `satisfied`.**
   A false "satisfied" silently retires a standard nobody will examine again.
2. **A probe or rule must never grade against a rubric wider than the standard it
   cites.** The conventional-commit probe once accepted four types `S1.19` did not
   list; it reported 98% where the truth was 90%. When the standard genuinely needs
   widening, amend the standard — `govern`/`decision` were added that way, and
   `harden` was refused in the same amendment. Law first, check second, never the
   reverse.
3. **Every regex quantifier is bounded**, and `scan_text` caps line length
   (`MAX_LINE_LENGTH`). `AP-D-FINTECH.3a` once took **8.7 seconds on one 20k-char
   line** — a DoS in every consumer's CI. A parameterised test times every rule
   against ten adversarial payloads; a new rule with unbounded quantifiers fails CI.
4. **Anything reaching a subprocess argument is validated as what it claims to be.**
   `git diff --output=<path>` writes a file; `--base` was interpolated unvalidated.
5. **Errors never echo URLs or credentials.** `urllib` includes the request URL in
   exceptions; endpoints may embed credentials; CI logs are widely readable.
6. **Evidence must resolve *inside* the repository.** An absolute path to any file on
   the machine is not evidence.
7. **Every new rule needs a positive *and* a negative test.** The negative — a
   repository doing exactly what a repository is for — is the one that matters.
8. **Core and domain metrics never mix.** Adding a domain must not move a number
   that tracks progress against the core.
9. **No AI references anywhere in the GitHub surface** — commits, PR/issue titles and
   bodies, branch names, co-authors, filenames. Human attribution only (`S1.100`).

### Workflow (`protocols/github-workflow.md`)

```
BRANCH  →  ISSUE  →  PR  →  MERGE
```

Branch first. Then an issue with **full metadata**: type, milestone (`Governova
v2.0`), project (`@KSDRILL's untitled project`), labels, assignee (`Maluleke-KS`).
Then a PR with `Closes #N` and the same metadata. Squash-merge, delete the branch.

```bash
gh issue create --title "..." --body-file /tmp/b.md --label enhancement \
  --milestone "Governova v2.0" --assignee Maluleke-KS
gh issue edit <N> --add-project "@KSDRILL's untitled project"
gh pr create --title "..." --body-file /tmp/p.md --base main --head <branch> \
  --label enhancement --milestone "Governova v2.0" --assignee Maluleke-KS
gh pr checks <N> --watch --interval 15
gh pr merge <N> --squash --delete-branch
```

**Commit types (`S1.19`, C1 v1.4): `feat` `fix` `docs` `chore` `refactor` `test`
`style` `perf` `ci` `govern` `decision` — and nothing else.**

`govern` is for a constitutional amendment, `decision` for an ADR. Both were added
by C0 §8 amendment on 2026-07-30. **`harden` was considered in that amendment and
refused** — security work is a `fix` when it closes a vulnerability and a
`chore`/`refactor` otherwise. One `harden:` commit remains a violation of record in
this repository's history; the probe still reports it, and that is correct.

If you need a type that does not exist, **amend `S1.19` first** — never widen the
probe. A test reads the type list out of the compiled `S1.19` and checks the probe
against it, so changing one without the other fails CI.

### 3. `#129` — pinned actions still target the deprecated Node 20 runtime

Every run annotates it. Nothing is broken because GitHub force-upgrades them, but it
affects all six workflows, so when the forcing stops they stop together — and an
annotation on every run trains everyone to ignore annotations. `S8.87` covers exactly
this: the external surface decays with no change to the repository.

### 4. Activate the semantic tier · **one repo setting**

Built, integrated, wired into `pr-guardian.yml`, and **inert** — it no-ops without a
`GOVERNOVA_LLM_*` secret. This is the only route to the ~93% of standards regex
cannot reach. Setting the secret is a repo-settings action.

### 5. Grow coverage honestly

Two legitimate routes, in preference order:

- **More structural probes** (`scripts/governova_evidence/`) — deterministic
  repository facts. Every probe added is mechanical evidence for every adopter, not
  just this repo. Existing eight are the pattern to follow.
- **More reliable-tier rules** where a genuine low-false-positive signature exists,
  including path-scoped ones for architectural standards.

**Do not** pad `governance/project.toml` with declarations to move the number.
Declarations are the weakest evidence the model accepts, and `S1.106`/`S1.107` are
deliberately left to the semantic tier because they have no deterministic signature —

## §5 — Traps that will cost you an hour

1. **`mypy` must run from `scripts/`.** From the root it errors on duplicate
   `__main__` modules.
2. **`ruff format` is *not* enforced in CI** — only `ruff check`. 22 files would be
   reformatted. Do not "fix" them; you will produce a huge unrelated diff.
3. **Heredocs mangle regex escapes.** `python - <<'PY'` with `\s` in a replacement
   string silently corrupts patterns. Use the Edit tool for regex changes.
4. **`platform/shared/types-py` is generated *and* committed.** Never hand-edit it —
   `governova-codegen --check` runs in CI and will fail. Change
   `scripts/governova_compile/schema.py`, re-run `governova-codegen --skip-ts`, and
   commit the result. The generator must stay deterministic (no timestamps, no
   SHAs) or the drift check becomes unusable; a test asserts this.
5. **The `compiled/constitution.json` checksum is content-only** — it excludes
   `compiled_at` and `source_commit_sha`, and line endings are normalised, so it is
   stable across platforms. If drift-check fails, you changed constitutional
   *content*. Run `governova compile` and commit the result.
6. **Two workspace members cannot share a name.** The root is
   `governova-workspace`; the publishable engine in `scripts/` is `governova`. Do not
   rename either back.
7. **`enforce.yml` pins `version: source`** so a PR is judged by the constitution the
   branch proposes, not a published build. Keep it.
8. **PowerShell `Push-Location scripts` fails if you are already in `scripts/`** and
   the subsequent `Pop-Location` then pops the wrong frame. Prefer
   `Set-Location C:\Users\Public\GITHUB\governova` at the start of each command.
9. **`Select-Object -First N` on a piped native command produces exit code 255.** It
   is a broken-pipe artifact, not a failure. Check `$LASTEXITCODE` on the command
   itself.
10. **`governova licences` must be run through `uv run`**, not via
    `PYTHONPATH=scripts python -m governova_cli`. It classifies *installed
    distributions*, so a bare interpreter reports on your global site-packages —
    unrelated tooling, often including copyleft — and fails on packages this project
    does not ship. The venv contains exactly the workspace closure, which is the set
    the gate is about. Same applies to `governova licences --sbom`.

### The one distinction that matters most

**Where the standards live** and **which repository is being governed** are different
questions. Conflating them confined the engine to its own repo for months —
invisible, because they are the same directory when Governova governs itself.

- `resolve_repo_root()` — the **authoring** tree. Requires `constitution/`. Only
  `compile`/`validate`/`codegen` may use it; those are maintainer operations.
- `resolve_target_root()` — the repository **under governance**. Git root, else cwd.
  **Never raises.**
- `load_active_index()` — the corpus to govern **with**. Precedence: explicit arg →
  `GOVERNOVA_CONSTITUTION` → working-tree `compiled/constitution.json` → bundled.

**That precedence is load-bearing.** A working-tree index beating the bundled one is
what keeps a PR judged by the constitution it proposes.

## §7 — Cutting a release

`governova` is on PyPI. v0.1.0 shipped 2026-07-30 via OIDC Trusted Publishing —
there is **no API token anywhere in this repository**, and there must not be. PyPI
trusts this owner, this repository, the workflow filename `release.yml`, and the
`pypi` environment. Change any of those four and publishing stops working, by design.

```bash
# 1. Bump the version — the workflow refuses a tag that disagrees with it.
#    scripts/pyproject.toml  ->  [project] version = "0.2.0"
# 2. Merge that through the normal branch → issue → PR → merge flow.
# 3. Tag the merged commit on main:
git tag -a v0.2.0 -m "governova 0.2.0" && git push origin v0.2.0
```

A merge never publishes; only a `v*` tag does. The workflow re-runs every gate
against the tagged commit — a tag can point anywhere — then builds, checks the wheel
carries the compiled constitution, **installs it into a clean venv and runs it in a
directory with no repository**, and only then uploads.

`workflow_dispatch` runs everything except the upload, which is how to test changes
to the release path itself. A routine PR does not exercise `release.yml`, so if you
touch it, dispatch it.

**Never hand-build and hand-upload.** The gates are the release.
