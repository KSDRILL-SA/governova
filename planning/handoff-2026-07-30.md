## §3 — Standing rules you must not violate

These were each established because the alternative was tried and failed. `ADR-006`
records the security ones.

1. **A check that cannot determine an answer returns `unknown`, never `satisfied`.**
   A false "satisfied" silently retires a standard nobody will examine again.
2. **A probe or rule must never grade against a rubric wider than the standard it
   cites.** The conventional-commit probe once accepted four types `S1.19` does not
   list; it reported 98% where the truth was 90%.
3. **Every regex quantifier is bounded**, and `scan_text` caps line length
   (`MAX_LINE_LENGTH`). `AP-D-FINTECH.3a` once took **8.7 seconds on one 20k-char
   line** — a DoS in every consumer's CI. A parameterised test times every rule
   against ten adversarial payloads; a new rule with unbounded quantifiers fails CI.
4. **Anything reaching a subprocess argument is validated as what it claims to be.**
   `git diff --output=<path>` writes a file; `--base` was interpolated unvalidated.
5. **Errors never echo URLs or credentials.** `urllib` includes the request URL in
   exceptions; endpoints may embed credentials; CI logs are widely readable.
6. **Evidence must resolve *inside* the repository.** An absolute path to any file on
   the machine is not evidence.
7. **Every new rule needs a positive *and* a negative test.** The negative — a
   repository doing exactly what a repository is for — is the one that matters.
8. **Core and domain metrics never mix.** Adding a domain must not move a number
   that tracks progress against the core.
9. **No AI references anywhere in the GitHub surface** — commits, PR/issue titles and
   bodies, branch names, co-authors, filenames. Human attribution only (`S1.100`).

### Workflow (`protocols/github-workflow.md`)

```
BRANCH  →  ISSUE  →  PR  →  MERGE
```

Branch first. Then an issue with **full metadata**: type, milestone (`Governova
v2.0`), project (`@KSDRILL's untitled project`), labels, assignee (`Maluleke-KS`).
Then a PR with `Closes #N` and the same metadata. Squash-merge, delete the branch.


**Commit types: `feat` `fix` `docs` `chore` `refactor` `test` `style` `perf` `ci` —

## §5 — Traps that will cost you an hour

1. **`mypy` must run from `scripts/`.** From the root it errors on duplicate
   `__main__` modules.
2. **`ruff format` is *not* enforced in CI** — only `ruff check`. 22 files would be
   reformatted. Do not "fix" them; you will produce a huge unrelated diff.
3. **Heredocs mangle regex escapes.** `python - <<'PY'` with `\s` in a replacement
   string silently corrupts patterns. Use the Edit tool for regex changes.
4. **`git status` always shows `platform/shared/` untracked** if you have run codegen.
   That is `#113`. Never `git add -A` blindly.
5. **The `compiled/constitution.json` checksum is content-only** — it excludes
   `compiled_at` and `source_commit_sha`, and line endings are normalised, so it is
   stable across platforms. If drift-check fails, you changed constitutional
   *content*. Run `governova compile` and commit the result.
6. **Two workspace members cannot share a name.** The root is
   `governova-workspace`; the publishable engine in `scripts/` is `governova`. Do not
   rename either back.
7. **`enforce.yml` pins `version: source`** so a PR is judged by the constitution the
   branch proposes, not a published build. Keep it.
8. **PowerShell `Push-Location scripts` fails if you are already in `scripts/`** and
   the subsequent `Pop-Location` then pops the wrong frame. Prefer
   `Set-Location C:\Users\Public\GITHUB\governova` at the start of each command.
9. **`Select-Object -First N` on a piped native command produces exit code 255.** It
   is a broken-pipe artifact, not a failure. Check `$LASTEXITCODE` on the command
   itself.

### The one distinction that matters most

**Where the standards live** and **which repository is being governed** are different
questions. Conflating them confined the engine to its own repo for months —
invisible, because they are the same directory when Governova governs itself.

- `resolve_repo_root()` — the **authoring** tree. Requires `constitution/`. Only
  `compile`/`validate`/`codegen` may use it; those are maintainer operations.
- `resolve_target_root()` — the repository **under governance**. Git root, else cwd.
  **Never raises.**
- `load_active_index()` — the corpus to govern **with**. Precedence: explicit arg →
  `GOVERNOVA_CONSTITUTION` → working-tree `compiled/constitution.json` → bundled.

**That precedence is load-bearing.** A working-tree index beating the bundled one is
what keeps a PR judged by the constitution it proposes.
