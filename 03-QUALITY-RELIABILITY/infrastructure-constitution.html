§ Part 1 — Environments (I1-I6)
Purpose

Consistent, isolated environments for each stage of the lifecycle.

PART 1 / I1-I6Environments4 Critical · 2 High
I1Required Environments — dev, staging, prodCritical

Three environments REQUIRED: development (local), staging (pre-production), production (live).

I2Staging Mirrors ProductionCritical

Staging MUST mirror production configuration (same env vars, same services, same settings). Scale down: fewer replicas, smaller instances.

I3No Production Data in Non-ProductionCritical

Production data MUST NOT be used in development or staging. Use anonymized test data only.

I4Environment Promotion OrderHigh

Environment promotion order: development → staging → production. NO skipping without tech lead approval.

I5Isolated DatabasesCritical

Each environment MUST have an isolated database. No cross-environment connections.

I6Configuration as CodeHigh

Environment configuration MUST be stored in code (version controlled). No manual changes to production configuration without code review.

§ Part 2 — Deployment Strategy (I7-I12)
Purpose

Safe, repeatable, fast deployments.

PART 2 / I7-I12Deployment Strategy3 Critical · 1 High · 2 Medium
I7Zero-Downtime DeploymentCritical

Zero-downtime deployment REQUIRED for production. User must not experience errors during deploy.

I8Rollback Time — 5 MinutesCritical

Deployment rollback MUST complete within 5 minutes of incident declaration.

I9Feature Flags RequiredHigh

Feature flags REQUIRED for all new features (Backend Constitution B42).

I10Canary Deployments (v1) — Not RequiredMedium

Canary deployments NOT required for v1. Use feature flags instead. Defer to v2.

I11Deployment FreezesMedium

Deployment freeze periods: 2 weeks before major holidays. Emergency fixes require tech lead approval.

I12Migrations Before CodeCritical

Database migrations MUST run BEFORE code deployment. Backward-compatible migrations only.

§ Part 3 — CI/CD Pipeline (I13-I18)
Purpose

Automated quality gates before deployment.

PART 3 / I13-I18CI/CD Pipeline4 Critical · 2 High
I13CI Pipeline on Every PRCritical

CI pipeline MUST run on every PR: type check → lint → unit test → build.

I14CD Pipeline on MergeCritical

CD pipeline MUST run on merge to main: integration test → migration → deploy staging → smoke test → deploy production.

I15Failed Pipeline Blocks DeploymentCritical

Failed CI/CD MUST block deployment. No force merge without tech lead approval.

I16CI Time Limit — 10 MinutesHigh

CI pipeline MUST complete within 10 minutes.

I17No Secrets in Logs or ArtifactsCritical

Secrets MUST NOT appear in CI/CD logs or build artifacts. Automated secret scanning REQUIRED.

I18Immutable Build ArtifactsHigh

Build artifacts MUST be immutable (never overwrite, always version). Same artifact deployed across environments.

§ Part 4 — Containerization (I19-I23)
Purpose

Consistent runtime across environments.

PART 4 / I19-I23Containerization & Orchestration3 High · 2 Medium
I19FastAPI Containerization RequiredHigh

FastAPI MUST be containerized (Docker) for deployment (Backend Constitution B35).

I20Next.js Deployment — Optional ContainerMedium

Next.js MAY use Vercel serverless (no container required) OR containerized deployment. Both acceptable for v1.

I21Container Image Tagging — Git Commit HashHigh

Container images MUST be tagged with git commit hash (short SHA). 'latest' tag is FORBIDDEN for production.

I22Container Vulnerability ScanningHigh

Container images MUST be scanned for vulnerabilities before deployment.

I23Kubernetes — Not Required (v1)Medium

Orchestration (Kubernetes) NOT required for v1. Use simpler platforms: Vercel (frontend), Render/Railway (backend).

§ Part 5 — Networking & Security (I24-I28)
Purpose

Secure, reliable network configuration.

PART 5 / I24-I28Networking & Security3 Critical · 1 High · 1 Medium
I24HTTPS Required — TLS 1.2+Critical

All external endpoints MUST use HTTPS with TLS 1.2 or higher. HTTP is FORBIDDEN for production.

I25DDoS Protection RequiredHigh

DDoS protection MUST be enabled. CloudFlare free tier (or equivalent) minimum.

I26Edge Rate LimitingHigh

API rate limiting MUST be configured at edge (before hitting application). Use CloudFlare Rate Limiting or Vercel Edge Config.

I27WAF — Not Required (v1)Medium

WAF (Web Application Firewall) NOT required for v1. Defer to v2 or when handling payments.

I28Security Headers RequiredCritical

Security headers MUST be configured: CSP, HSTS, X-Frame-Options, X-Content-Type-Options.

§ Part 6 — Observability Infrastructure (I29-I32)
Purpose

See what's happening, debug quickly.

PART 6 / I29-I32Observability Infrastructure1 Critical · 3 High
I29Centralized LoggingHigh

Centralized logging MUST be configured. Better Stack, Datadog, or Loki + Grafana minimum.

I30Metrics DashboardHigh

Metrics dashboard MUST show: latency (p50/p95/p99), error rate, request count, resource usage.

I31Uptime Monitoring — 1 Minute PingsHigh

Uptime monitoring MUST ping critical endpoints every 1 minute. Alert on failure after 2 consecutive failures.

I32On-Call AlertingCritical

On-call alerting MUST be configured for P0/P1 incidents. PagerDuty, Opsgenie, or Better Stack on-call minimum.

§ Part 7 — DR & High Availability (I33-I36)
Purpose

Plan for failure, recover quickly.

PART 7 / I33-I36Disaster Recovery & High Availability2 High · 2 Medium
I33Multi-Region — Not Required (v1)Medium

Multi-region deployment NOT required for v1. Single region is acceptable. Defer to v2 for global scale.

I34Read Replicas — Not Required (v1)Medium

Database read replicas NOT required for v1. Single primary is acceptable. Defer to v2 for read-heavy workloads.

I35DR Runbook RequiredHigh

Disaster Recovery runbook MUST exist and be tested quarterly (Database Constitution D29).

I36RTO/RPO from Database ConstitutionHigh

RTO (4 hours) and RPO (24 hours) from Database Constitution MUST be documented and achievable.

§ Part 8 — Cost Management (I37-I40)
Purpose

Control cloud costs, prevent surprise bills.

PART 8 / I37-I40Cost Management2 High · 2 Medium
I37Staging Cost OptimizationHigh

Staging environment MUST be cost-optimized: smaller instances, fewer replicas, auto-off during off-hours (optional).

I38Unused Resource Termination — Monthly ReviewMedium

Unused resources (load balancers, volumes, old snapshots) MUST be reviewed monthly. Automated termination NOT required for v1.

I39Monthly Cost Review — 5 MinutesMedium

Monthly cost review MUST be performed (5 minutes in sprint retrospective). Review top 5 cost drivers, unexpected increases, unused resources.

I40Budget Alerts — 50/80/100%High

Budget alerts MUST be configured at 50%, 80%, and 100% of monthly budget. Alert via email and Slack.

§ v1.1 Enhancements — CI/Test Split, Rollback Verification, RTO Exception, Quarterly Review (I41-I44)
Purpose

Address identified gaps and strengthen v1.0 foundation.

v1.1 / I41-I44Enhancements2 Critical · 1 High · 1 Medium
I41CI/Test Split StrategyHigh

Test suite MUST be split into fast (<3 min) and full (<10 min) suites. Fast suite runs on every PR; full suite runs pre-merge to main.

4-hour RTO (I36) excludes cloud provider regional outages. Regional outage RTO is "as long as provider recovery time." This exception MUST be documented in DR runbook.
